== Introduction

This ReadMe complements the machine-readable link:https://github.com/entsoe/relicapgrid/blob/cgmes-3.0_ncp-2.4_tc-1.1/Instance/Belgovia/Grid/manifest.ttl[manifest] and provides a human-readable description of the **Belgovia Grid Model** within the
*ReliCapGrid* repository.

Belgovia is a synthetic power system model (Individual Grid Model, IGM) created for testing, demonstration, and interoperability purposes.  
It does not represent a real TSO grid.

The model is compliant with the *IEC Common Grid Model Exchange Standard (CGMES)*, as well as *ENTSO-E Network Code data exchange specifications* (profiles).
The datasets are validatied with SHACL contraints available in link:https://github.com/entsoe/application-profiles-library[ENTSO-E Application Profiles Library] repository and are subject to review by the ENTSO-E Standard Vetting Interoperability Tests (SV-IOP).

== Model Scope and Content

The Belgovia model represents a single control area and includes datasets organised into the following folders:

* *Grid* – Static and operational grid model datasets, covering the following CGMES profiles:
** EQ – Equipment
** TP – Topology
** SSH – Steady-State Hypothesis
** SV – State Variables

* *NetworkCode* – Network Code profile datasets, covering:
** AE – Assessed Element
** CO – Contingency
** ER – Equipment Reliability
** PS – Power Schedule
** RA – Remedial Action
** RAS – Remedial Action Schedule
** RAS_FAP – Remedial Action Schedule (FAP process)
** SHS – Steady-State Hypothesis Schedule
** SIS – State Instruction Schedule

* *GridSituation* – Planned for future development; will describe specific operational snapshots of the grid.

* *ChangeSet* – Planned for future development; will contain incremental model updates (deltas) representing objects added, modified, or deleted relative to a base model.

== Package Structure and Serializations

The package is provided in multiple serializations:

* `cimxml/` –  According to *IEC 61970-552:2016* which is the main serialization used for *IEC 61970-600-1* (CGMES) datasets and for ENTSO-E Network Code profiles.

* `jsonld/` –  
  CIM JSON-LD representations aligned with *IEC 61970-553* (under development), enabling integration with semantic and data-driven tooling.
  This serialization is not currently provided and may be added in the future to support semantic and data-driven tooling. (CIM JSON-LD is generated from CIMXML.)

* `trig/` – link:https://www.w3.org/TR/trig/[TriG] representation for improved readability and semantic inspection. (TriG is generated from CIMXML.)
